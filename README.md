# Homework Bot

Telegram-бот, который следит за статусом проверки домашней работы в Яндекс Практикуме и сам сообщает, когда статус меняется. Больше не нужно обновлять страницу курса в ожидании ревью.

## Как работает

Раз в 10 минут бот обращается к API Практикума и проверяет, изменился ли статус последней отправленной работы. При изменении бот присылает сообщение в Telegram:

| Статус | Сообщение |
|---|---|
| `reviewing` | Работа взята на проверку ревьюером. |
| `approved` | Работа проверена: ревьюеру всё понравилось. Ура! |
| `rejected` | Работа проверена: у ревьюера есть замечания. |

## Возможности

- При запуске проверяется, что все переменные окружения на месте. Если чего-то не хватает, бот завершается с понятной ошибкой.
- Ответ API проверяется на соответствие документации: тип данных, наличие ключей, известный статус.
- Собственные исключения для разных видов сбоев: `MissingTokenError`, `InvalidResponseError`, `UnknownStatusError`.
- Все события логируются: отправленные сообщения, отсутствие новых статусов, ошибки.
- О сбоях в работе бот сообщает в Telegram, но одну и ту же ошибку не присылает повторно.
- Метка времени последней проверки обновляется только после успешной отправки сообщения, поэтому статусы не теряются.

## Как развернуть проект

Клонировать репозиторий и перейти в него:

```bash
git clone git@github.com:Rufina007/homework-bot.git
cd homework-bot
```

Создать и активировать виртуальное окружение:

```bash
python3 -m venv venv
source venv/bin/activate        # Linux / macOS
source venv/Scripts/activate    # Windows
```

Установить зависимости:

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Создать в корне проекта файл `.env`:

```
PRACTICUM_TOKEN=<токен API Практикума>
TELEGRAM_TOKEN=<токен Telegram-бота>
TELEGRAM_CHAT_ID=<ваш ID в Telegram>
```

Где взять значения:

- `PRACTICUM_TOKEN`: получить по ссылке из урока о боте в курсе Практикума, нужно быть авторизованным в Практикуме;
- `TELEGRAM_TOKEN`: создать бота у [@BotFather](https://t.me/BotFather);
- `TELEGRAM_CHAT_ID`: узнать у [@userinfobot](https://t.me/userinfobot).

Запустить бота:

```bash
python homework.py
```

Для деплоя на сервер в проекте есть `Procfile` (`worker: python homework.py`).

## Выводы

- Работа с внешним API требует проверять каждый уровень ответа: статус-код, тип данных, наличие ключей. Иначе неожиданный ответ роняет программу.
- Собственные исключения делают логи и сообщения об ошибках понятнее, чем общий `Exception`.
- Бот, который работает без присмотра, должен сам сообщать о своих сбоях, но не спамить одинаковыми ошибками.
